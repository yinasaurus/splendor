PART E - HOW TO RUN (TALKING POINTS)
================================================================================

Console
  compile.bat then run.bat (or .sh equivalents).
  Follow prompts; supports multiple humans and AI seats.

Web
  compile.bat then run_web.bat.
  Default http://localhost:8080/ (or PORT env var if supported).
  Create room or join with code; ready; owner starts match.
  State: GET /api/state?room=...&name=...&sessionToken=...
  Actions: POST /api/action JSON body with room, name, sessionToken, type, ...

If the port is busy, change PORT or stop the other process.

PART F - WEB LAYER (ARCHITECTURE FOR SLIDES)
================================================================================

Single-threaded executor on HttpServer reduces race conditions from double clicks.

Static files
  /              -> web/index.html
  /styles.css, /app.js, /config.js
  /media/...     -> media/ at project root (sprites, card art)

JSON API (representative)
  GET  /api/state
       Returns full board JSON: players, gems, visible cards, nobles, lobby,
       recentActions, chat[], turn flags, gameOver, etc.

  POST /api/chat
       Body: room, name, sessionToken, message (or text). Seated players only.
       Chat capped server-side; history included in /api/state.

  POST /api/action
       type examples: takeGems, reserve, reserveTop, purchaseVisible,
       purchaseReserved, pass
       Engine runs move; on success, advanceTurnsAfterHuman runs AI chain.

  POST /api/room/create, /api/room/join, /api/room/ready, /api/room/start
  POST /api/room/addai, /api/room/kick, /api/room/rename, /api/room/afkai
  POST /api/newgame, /api/quit

AI turns
  advanceTurnsAfterHuman(session) - after each successful human action, nextTurn
  then while current is AI, makeMove, then nextTurn, until human or game over.

  runAiTurnsWhileCurrentIsAi(session) - called when a match STARTS (room start,
  newgame handler, snapshot recovery) so if the first player in turn order is
  AI, they actually move (otherwise nothing triggered the first AI).

Browser (web/)
  app.js - fetchState, postAction, lobby, live sync interval, renderState,
           gameUiNav for rematch/home from game-over overlay, table chat UI,
           prestige alerts, etc.
  index.html - layout, game-over card, chat panel, rulebook overlay
  styles.css - layout, game-over mode, player cards, chat

PART K - EXAM-STYLE Q&A (SHORT ANSWERS)
================================================================================

K1) Why separate GameRules from GameController?
    Rules answer "is this legal?"; controller applies state changes after checks.
    Stops duplication and keeps validation in one place.

K2) Why externalize winning.points in config.properties?
    Change game length without recompiling; meets spec for external config.

K3) What happens when a player reaches winning prestige?
    endgamePending; each other player gets one more turn; then winner by prestige
    and tie-break (fewer development cards).

K4) Why does the web server call nextTurn and AI in a loop after a human move?
    The controller action methods do not always advance the current player index
    the same way for every path; the server normalizes "end of human turn" by
    advancing and then simulating AI seats until a human is up or game ends.

K5) Why was runAiTurnsWhileCurrentIsAi needed?
    advanceTurnsAfterHuman only runs after a human POST /api/action. At match
    start the first player might be AI; no human action happened yet, so AIs
    must be run once when the game becomes active.

K6) What is validated on take three different gems?
    Exactly three distinct non-gold colors; bank must have each; player cannot
    exceed max gems (often 10) without discarding per rules implementation.

K7) How does reserve interact with gold and gem cap?
    If gold available, player receives one gold; if over cap, discard to bank
    (web path supports explicit discard map for client UX).

K8) Name two reasons illegal moves must be rejected server-side, not only in JS.
    Cheating via crafted requests; second client / refresh bypassing UI.

K9) What does GameBoard need to draw a new visible card after purchase?
    Remove bought card from slot; draw from same level deck; refill slot.

K10) AIStrategy pattern benefit?
    Swap difficulty without changing GameController or Player; open/closed style.

K11) What is in /api/state JSON "lobby" object?
    owner, gameStarted, numPlayers, canStart, players list with ready flags
    and AI flags - used before and during match for UI.

K12) Why seat tokens for web players?
    So the same display name cannot hijack another browser session mid-game.
